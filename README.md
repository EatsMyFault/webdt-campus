# Smart Factory Campus Digital Twin

Three.js와 Vite로 구현한 웹 기반 스마트 팩토리 단지 디지털 트윈 프로토타입입니다.

1,240 × 900 m 규모의 단지에 생산 A동, 생산 B동, 유틸리티 센터, 물류·출하 센터를 배치하고 시설 탐색, 설비 상태 확인, 출입문 제어와 물류 운행 시뮬레이션을 브라우저에서 제공합니다.

## 주요 기능

### 단지와 카메라

- 4개 시설을 포함한 스마트 팩토리 단지와 외곽 환경
- 단지 전체 및 시설별 빠른 카메라 이동
- 시설별 외부, 내부, 세부 구역, 2D 평면 시점
- 마우스 회전·평행 이동·확대/축소와 WASD 자유 이동
- 카메라 거리와 현재 시설에 따른 건물 라벨 표시 제어
- 자동·낮음·중간·높음 그래픽 품질 설정

### 생산 A동

- 정밀가공 설비와 내부 생산라인
- 산업용 출입문 개폐 제어
- 공압 지원실과 생산라인 연결
- 설비 더미 데이터와 상세정보 UI
- 런타임에서 A동 GLB 모델 로딩

### 생산 B동

- 스마트 조립 생산라인과 연속 컨베이어
- 조립 출입문 개폐 제어
- 설비 더미 데이터와 상세정보 UI
- 실내 및 2D 평면 시점

### 유틸리티 센터

- 저장 탱크, 냉각기, 변압기 등 유틸리티 설비
- 메인 배관과 개별 설비 배관 연결
- 배관 유량 애니메이션
- 유틸리티 전용 상세정보 UI

### 물류·출하 센터

- 물류 창고, 적재 구역, 출하 도크
- 다중 도크 셔터 개폐 제어
- 트럭 GLB 모델 배치
- 입차 → 대기 → 상하차 → 출차 운행 애니메이션
- 물류 설비 데이터와 전용 상세정보 UI

### 관제 UI

- 전체 및 시설별 설비 상태 요약
- 설비 목록과 상태 필터
- 선택 설비 상세정보
- 설비 종류별 상세정보 UI 분기
- 물류 운행 상태와 제어 패널

### 데모 시나리오

- A동 CNC 과열 → 경고 → 안전 정지 → 냉각 → 정상 복귀
- 시나리오 재생, 일시정지, 초기화
- 설비 상세정보, 관제 수량, 3D 상태등 동기화
- 시간순 상태 변화 이벤트 기록

## 기술 스택

- JavaScript ES Modules
- Three.js
- Vite
- GLTF/GLB
- HTML5 / CSS3

## 요구 환경

- Node.js 20 이상 권장
- npm
- WebGL2를 지원하는 최신 Chrome, Edge 또는 Firefox

## 설치 및 실행

```powershell
cd E:\WebDt\webdt-campus
npm.cmd install
npm.cmd run dev
```

터미널에 표시되는 주소를 브라우저에서 엽니다. 기본 주소는 일반적으로 `http://localhost:5173`입니다.

## 프로덕션 빌드

```powershell
npm.cmd run build
```

빌드 결과물은 `dist` 폴더에 생성됩니다. 결과물을 로컬에서 확인하려면 다음 명령을 사용합니다.

```powershell
npm.cmd run preview
```

## 테스트

```powershell
npm.cmd test
```

## A동 GLB 내보내기

```powershell
npm.cmd run export:factory-a
```

## 기본 조작

- 마우스 드래그: 카메라 회전 또는 평행 이동
- 마우스 휠: 확대/축소
- `W`, `A`, `S`, `D`: 현재 시점 기준 수평 이동
- `Q`, `E`: 카메라 높이 이동
- `Shift`: 빠른 이동
- 숫자 `0`~`4`: 단지 전체/A동/B동/유틸리티/물류 시점 이동
- 3D 설비 클릭: 상세정보 표시

활성화된 2D/3D 시점과 상세정보 UI 상태에 따라 일부 입력은 제한될 수 있습니다.

## 설비 데이터 구조

현재는 시설별 JavaScript 파일에 정의된 더미 데이터를 사용합니다. `equipmentDataRegistry.js`가 A동, B동, 유틸리티동, 물류동 데이터를 합쳐 설비 ID로 조회합니다.

설비를 추가할 때는 다음 값이 반드시 일치해야 합니다.

1. 3D 객체의 `equipmentId`
2. 데이터 파일의 설비 `id`

향후 중앙 상태 저장소를 추가하고 HTTP API와 WebSocket에서 받은 데이터를 이 저장소에 반영할 예정입니다.

## 배포 참고

- 테스트 서버에는 `npm.cmd run build`로 생성한 `dist` 폴더의 내용을 업로드합니다.
- `node_modules`와 로컬 환경 파일은 Git 또는 서버에 업로드하지 않습니다.
- 외부 GLB, 이미지, 폰트는 배포 전에 라이선스와 출처를 확인해야 합니다.
