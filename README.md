# 카펙발레오 영천공장 디지털 트윈

Three.js와 Vite로 구현한 웹 기반 배터리 시스템 공장 디지털 트윈 프로토타입입니다.

카펙발레오 영천공장을 모델로, 외부 조달한 각형 셀을 받아 모듈을 만들고 완성 팩까지 조립·시험하는 공정을 1,240 × 1,052 m 규모의 단지에 담았습니다. 시설 탐색, 설비 상태 확인, 출입문 제어와 물류 운행 시뮬레이션을 브라우저에서 제공합니다.

설비 수치와 생산 실적은 모두 UI 검증용 더미 데이터입니다.

## 공정 흐름

단지는 반시계 방향 U자 흐름으로 배치했습니다. 완성 팩은 무겁고 부피가 커서 출하 동선을 최단으로 두고, 상대적으로 빈도가 낮은 셀 반입에 긴 구간을 배정했습니다.

```text
   ┌─────────────────┐   ② 모듈    ┌─────────────────┐
   │  MA-01          │ ──────────▶ │  PA-01          │
   │  모듈 조립동     │             │  팩 조립동       │
   │  셀검사 → EOL    │             │  트레이 → 팩 EOL │
   └─────────────────┘             └─────────────────┘
        ▲ ① 셀 반입                        │ ③ 완성 팩
        │                                  ▼
   ┌─────────────────┐   ④ 유틸리티 ┌─────────────────┐
   │  UT-01          │ ┈┈┈┈┈┈┈┈▶  │  LG-01          │
   │  유틸리티 플랜트 │             │  자재·출하 물류   │
   └─────────────────┘             └─────────────────┘
```

| 순서 | 공정 | 건물 |
| --- | --- | --- |
| 1 | 셀 수입검사 | 모듈 조립동 |
| 2 | 셀 스태킹 | 모듈 조립동 |
| 3 | 버스바 레이저 용접 | 모듈 조립동 |
| 4 | 모듈 EOL 검사 | 모듈 조립동 |
| 5 | 트레이·쿨링플레이트 | 팩 조립동 |
| 6 | 모듈 장착·결선 | 팩 조립동 |
| 7 | 실링·기밀검사 | 팩 조립동 |
| 8 | 팩 EOL 시험 | 팩 조립동 |

공정 순서와 설명은 `src/config/processConfig.js` 한 곳에서 관리하며, 건물 이름과 시점 부제가 이를 따릅니다.

## 주요 기능

### 단지와 카메라

- 5개 시설을 포함한 공장 단지와 외곽 환경
- 단지 전체 및 시설별 빠른 카메라 이동
- 시설별 외부, 내부, 세부 구역, 2D 평면 시점
- 마우스 회전·평행 이동·확대/축소와 WASD 자유 이동
- 카메라 거리와 현재 시설에 따른 건물 라벨 표시 제어
- 자동·낮음·중간·높음 그래픽 품질 설정

### 모듈 조립동 (MA-01)

- 셀 전기특성 검사기와 외관 비전 검사기
- 셀 스태킹 자동화 설비와 셀 보관 랙
- 버스바 레이저 용접기와 용접부 3D 비전 검사기
- 모듈 EOL 충방전 시험기, 절연내압 시험기
- 용접 흄 집진기, 제습 공조기, 공기압축기
- 산업용 출입문 개폐 제어
- 런타임에서 GLB 모델 로딩

### 팩 조립동 (PA-01)

- 팩 트레이 세정기와 열전도 접착제 디스펜서
- 모듈 장착 로봇과 고전압 버스바 체결기
- BMS·BDU 장착 스테이션
- 커버 실런트 도포 로봇, 냉각수 진공 주입기, 기밀 누설 시험기
- 팩 EOL 충방전 시험기, 절연·고전압 안전 시험기, 레이저 각인 검사기
- 구내 운반 AGV
- 출입문 개폐 제어
- ㄷ자 이송 컨베이어와 벨트 양옆 스테이션 배치
- 팩 단위 운행 시뮬레이션. 병목 앞 정체와 뒤 공백이 그대로 나타남

#### 라인 밸런싱

같은 설비 종류(`type`)가 한 공정을 나눠 맡는 병렬 뱅크입니다. 사이클이 긴 공정일수록 대수를 늘려 목표 택트 60초 안에 들어오게 했습니다.

| 공정 | 대수 | 최장 사이클 | 유효 택트 |
| --- | --- | --- | --- |
| 트레이 세정 | 1 | 52.4초 | 52.4초 |
| 열전도 접착제 도포 | 2 | 49.0초 | 24.5초 |
| 모듈 장착 로봇 | 4 | 69.6초 | 17.4초 |
| 고전압 버스바 체결 | 2 | 76.0초 | 38.0초 |
| BMS·BDU 장착 | 2 | 88.4초 | 44.2초 |
| 커버 실링 도포 | 2 | 99.0초 | 49.5초 |
| 냉각수 진공 주입 | 3 | 124.6초 | 41.5초 |
| 팩 기밀 누설 시험 | 3 | 122.0초 | 40.7초 |
| **팩 EOL 충방전** | **5** | **280.0초** | **56.0초 ← 병목** |
| 절연·고전압 안전 시험 | 1 | 42.8초 | 42.8초 |
| 레이저 각인·최종 비전 | 1 | 18.4초 | 18.4초 |

병목인 팩 EOL이 라인 택트를 **56초**로 정합니다. 컨베이어는 그 시간에 스테이션 한 칸을 지나갑니다.

밸런싱은 두 기준으로 봅니다.

| 기준 | 세는 대상 | 쓰임 |
| --- | --- | --- |
| **설치 기준** | 깔아 놓은 설비 전부 | 라인 설계가 목표 택트를 만족하는지 |
| **가동 기준** | 지금 돌아가는 설비만 | 실제 라인 속도. 컨베이어가 이걸 따라감 |

관제 패널의 **LINE BALANCE** 섹션이 가동 기준 밸런싱을 실시간으로 보여 줍니다. 공정별로 `가동/설치` 대수, 최장 사이클, 유효 택트가 나오고, 병목에는 표식이 붙습니다. 목표 택트를 넘긴 공정은 주황색으로 바뀝니다.

설비가 멈추면 그 뱅크의 유효 택트가 느려지고, **병목이 다른 공정으로 옮겨 가기도 하며, 벨트도 그만큼 느려집니다.** 뱅크가 통째로 서면 라인 전체가 멈춥니다.

예를 들어 기본 데이터는 팩 EOL 시험기 5대 중 4호기가 대기 상태라, 설계 택트는 56초지만 **실제 라인은 70초**로 돌아갑니다. 패널에도 그렇게 나옵니다.

#### 병목이 라인에 나타나는 모습

컨베이어 위 팩은 하나씩 따로 움직입니다. 팩마다 설비에 올라가 사이클 타임을 채우고, 다음 공정에 자리가 나야 넘어갑니다. 공정 사이 벨트에는 대기 칸이 몇 개뿐이라, 그 칸이 차면 앞 공정 설비가 완성품을 못 내려놓고 그대로 붙잡힙니다. 이 막힘이 위로 번지면서 병목 앞 구간이 팩으로 꽉 찹니다.

기본 데이터 기준 정상 상태(팩 39대):

```text
라인 시작 ────────────────── 팩 EOL(병목) ── 라인 끝
  #####  ######  ####  ####  ##  ###  ######  ####  ####  #
                              병목 앞 34대 │ 뒤 5대
```

마지막 각인·검사기는 병목 뒤라 자주 비어 있습니다. 설비를 세우면 그 공정 앞에 새로 줄이 서고, 뱅크가 통째로 서면 그 지점에서 라인이 막힙니다.

화면을 열자마자 이 분포가 보이도록 시뮬레이션을 90분치 미리 돌려 두고 시작합니다.

`packLineBalance.js`가 설비 데이터에서 이 계산을 하므로, 사이클 타임이나 대수를 고치면 패널과 컨베이어 속도가 함께 바뀝니다. 병목이 목표 택트를 넘으면 `tests/packLineBalance.test.mjs`가 실패합니다.

### 관제 UI

- 전체 및 시설별 설비 상태 요약
- 설비 목록과 상태 필터
- 선택 설비 상세정보, 설비 종류별 UI 분기
- 팩 조립동 라인 밸런싱과 실시간 병목 표시
- 물류 운행 상태와 제어 패널
- 초 단위 현재 날짜·시각 표시
- 건물별 KPI 대시보드

| 건물 | KPI 카드 |
| --- | --- |
| 모듈 조립동 | 설비 가동률 · 모듈 생산량 · 직행률 · 에너지 사용량 |
| 팩 조립동 | 설비 가동률 · 팩 생산량 · 직행률 · 에너지 사용량 |
| 유틸리티 플랜트 | 설비 가동률 · 수전 전력 · 냉각수 사용량 · 압축공기 압력 |
| 자재·출하 물류 | 설비 가동률 · 입출고 처리 · 도크 점유율 · 구내 운행 트럭 |

배터리 공정은 불량률보다 **직행률(FTT)** 을 본다는 점을 반영해, 생산동 KPI는 재작업 없이 한 번에 통과한 비율로 표시합니다.

## 설치 및 실행

```bash
npm install
npm run dev
```

터미널에 표시되는 주소를 브라우저에서 엽니다. 기본 주소는 일반적으로 `http://localhost:5173`입니다.

## 프로덕션 빌드

```bash
npm run build
```

빌드 결과물은 `dist` 폴더에 생성됩니다. 결과물을 로컬에서 확인하려면 다음 명령을 사용합니다.

```bash
npm run preview
```

## 테스트

```bash
npm test
```

## 모듈 조립동 GLB 내보내기

모듈 조립동은 런타임에 `public/models/factory-a.glb`를 읽습니다. **`src/interiors/createFactoryAInterior.js`나 `src/buildings/createProductionFactory.js`를 고친 뒤에는 반드시 내보내기를 다시 실행해야 화면에 반영됩니다.**

```bash
npm run export:factory-a
```

내보낸 GLB가 최신 소스와 맞는지 확인하려면 다음 명령을 사용합니다.

```bash
node scripts/inspectFactoryAGlb.mjs
```

## 기본 조작

- 마우스 좌클릭 드래그: 시점 회전 (2D 평면 시점에서는 동작하지 않음)

- 숫자 `0`~`5`: 단지 전체/모듈동/팩동/유틸리티/물류/운영동 시점 이동
- 3D 설비 클릭: 상세정보 표시

활성화된 2D/3D 시점과 상세정보 UI 상태에 따라 일부 입력은 제한될 수 있습니다.

## 설정과 데이터 구조

사업장 정체성과 공정 정의는 단일 소스로 분리했습니다.

| 파일 | 역할 |
| --- | --- |
| `config/companyConfig.js` | 회사·사업장 이름, 문서 타이틀, 제품군 |
| `config/processConfig.js` | 8단계 공정 순서와 건물 배정 |
| `config/buildingConfig.js` | 건물 식별자, 표시 이름, 배치 좌표 |
| `data/packLineBalance.js` | 팩 조립 라인 병렬 뱅크와 택트 계산 |

설비 데이터는 시설별 JavaScript 파일의 더미 데이터를 사용합니다. `equipmentDataRegistry.js`가 모듈 조립동, 팩 조립동, 유틸리티, 물류 데이터를 합치고, `equipmentStore.js`가 실행 중인 설비 상태를 관리합니다.

설비를 추가할 때는 다음 값이 반드시 일치해야 합니다.

1. 3D 객체의 `equipmentId`
2. 데이터 파일의 설비 `id`
3. 설비의 `processStep`과 `processConfig.js`의 공정 `id`

이 세 가지는 `tests/equipmentIdConsistency.test.mjs`가 자동으로 검증합니다. 건물 식별자(`factory-a`, `factory-b`)는 GLB 파일과 시점 설정이 함께 쓰므로 바꾸지 않고, 표시 이름만 공정에 맞춥니다.

실제 데이터 연결 시 HTTP API와 WebSocket에서 받은 값을 설비 저장소와 KPI 데이터 공급부에 반영하도록 교체할 수 있습니다.

- `node_modules`와 로컬 환경 파일은 Git 또는 서버에 업로드하지 않습니다.
- 외부 GLB, 이미지, 폰트는 배포 전에 라이선스와 출처를 확인해야 합니다.

## 개발 상태

현재 프로젝트는 기능 검증과 시연을 위한 프로토타입입니다. 배치와 설비 구성은 공개 정보와 일반적인 배터리 팩 공정 지식을 바탕으로 구성한 것이며, 실제 영천공장의 도면이나 설비 목록을 반영한 것이 아닙니다.

실제 운영 환경에서는 API 인증, WebSocket 재연결, 데이터 유효성 검사, 오류 처리, 접근 권한, 성능 측정과 모니터링이 추가로 필요합니다.
